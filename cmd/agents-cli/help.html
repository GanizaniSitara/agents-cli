Get started

  1. Put agents-cli.exe in a folder you want to keep. No installer is required.
  2. Open a terminal in that folder and run:
.\agents-cli.exe watch start

The panel appears and the watcher continues in the background. Open Settings to choose the monitor, desktops and shortcuts. If the executable is on your PATH, you can use agents-cli without the .\ prefix.

It recognises supported CLI consoles, including Claude Code, Codex, Copilot CLI, AGY, Vibe, OpenCode and Qwen. Classic Windows console windows support the window attention effects. Terminal tabs and native/browser chat apps do not have the same coverage.

Observing is not delegating. The watcher does not send prompts or recruit other sessions as workers. An unrelated session appearing in the panel is not permission to message it.

Nothing is added to Windows startup. Run watch start again after signing in.

Read the panel

NEEDS INPUT

An approval or other input request is waiting. QUESTION and REVIEW also use amber.

IDLE

The session appears idle. This alone does not prove that the task is finished.

FINISHED

A completion indicator was detected.

ERROR

An error or usage-limit indicator was detected in the session.

RUNNING

Work appears to be in progress. Running sessions stay below attention rows.

ACTIVE

This is the focused window. Focus is not evidence that the agent is working.

UNKNOWN

The watcher cannot currently establish the state. Check the actual console.

PARKED

An idle session you have put at the bottom of the list.

Each row identifies the session and provider, with age, available context information and sub-agent counts when those can be established. Counts stay unknown when there is no reliable source.

Status detection is heuristic. When the panel and console disagree, use the console and report the diagnostic details below.

Controls & settings

Find a session

  • Click a row to select its window.
  • Double-click a row for a bright white locator pulse.
  • A normal selection pulses the title bar in the row's colour: blue, amber, red or the configured colour.
  • Visible windows keep their size and position. Minimized windows may be restored.

Move or hide the panel

  • Drag the panel header to move it.
  • Hide keeps the watcher running. Click its tray icon to show it again.
  • Exit, in Settings or the tray right-click menu, stops only the watcher. Agent sessions keep running.

Park or dismiss

  • Park is below the row number and close control. It puts an idle session at the bottom and excludes it from the first-row shortcut.
  • ^ unparks it. New work or input requests also clear parking.
  • Parking lasts for the current watcher run.
  • x dismisses the row from the panel; it does not close the agent.

Settings

  • Blink selected window controls the selection pulse.
  • Bring selected window forward controls activation.
  • Allow selection to switch desktops permits following an explicitly selected session to another desktop.
  • Reset location returns the panel to its default position. Done returns to the session list.

Global shortcuts

Default first-row shortcut: Ctrl + Win + Z. It targets the first eligible row currently displayed, skipping parked sessions.

Default numbered shortcuts: Ctrl + Alt + Shift + 1–9, 0, for the first ten displayed rows. The two bindings are independently changeable or can be turned off in Settings. Existing explicit Off choices are preserved.

Release the shortcut keys before activation. Global bindings can clash with other software or Windows; Settings reports registration failures. Neither shortcut sends a prompt or presses Enter in the agent.

The command line

These examples assume agents-cli.exe is on PATH. Otherwise use .\agents-cli.exe from its folder. Commands return JSON.

agents-cli version
agents-cli ls --fast
agents-cli ls
agents-cli tail 12345 --lines 20
agents-cli watch list
agents-cli watch stop
agents-cli sends --since 1d --limit 50
agents-cli help

Replace 12345 with the actual session PID from ls. ls --fast lists metadata; ls also reads state. watch stop stops the background watcher, not agent sessions. Open this guide with agents-cli help --open.

Sending to a session you are authorized to control

Inspect its fresh tail first. Confirm that it is the intended agent, not a bare shell, another task or a permission dialog. Discovery and a matching provider name do not authorize reuse of someone else's conversation.

From Windows cmd, send the contents of a text file without putting the message in process arguments:

agents-cli send 12345 --stdin < message.txt
agents-cli tail 12345 --lines 20

--no-enter only types. agents-cli key 12345 enter sends a named key. The send receipt distinguishes submission from merely typing the message. If submission is unverified or the command times out, inspect the target before retrying.

Ordinary sends and key actions are logged with caller and target identifiers. Other providers' native messaging tools and manual typing are outside this audit.

When something looks wrong

If the header shows reader retrying or a WR code, the watcher has a reading problem. This is separate from an agent session's own error status.

agents-cli version
agents-cli watch list
agents-cli sends --since 1d --limit 50

For a report, include the build, visible code, last_reader_error, last_console_error and reader_restarts. The last failures remain available after recovery for the current watcher run. A reported PID is the last known target, not proof that it caused the failure.

CodeMeaning
WR101Reader could not start or create its pipe.
WR102No reader heartbeat arrived within the deadline.
WR103Invalid structured reader data.
WR104Reader watchdog timeout.
WR105Reader exited unexpectedly; check its exit status.
WR106Reader pipe failed or a record was too large.
WR107Process/session discovery failed.
WR108A particular console was unreadable; other sessions may still be healthy.

Unknown states can occur with unsupported console hosts or unreadable background processes. A steady blue taskbar-button background is not implemented; the coloured selection pulse is a separate effect.

Local data & sharing

The guide is embedded in the executable and uses no remote assets, analytics or web service. Opening it writes a local HTML copy. No provider credentials are required by the watcher.

Share the reviewed executable or release package, not your runtime folders. Logs and settings are local files and are not encrypted by Agents CLI.

  • %LOCALAPPDATA%\agents-cli\watch: watcher status, settings and diagnostics. Names and window titles may contain private information.
  • %LOCALAPPDATA%\agents-cli\sends.jsonl: send/key audit, plus one rotated predecessor; about 8 MiB total.

The send audit includes timestamps, caller and target process/session identifiers, method, message byte count and outcome. It excludes message bodies, hashes, titles, command lines and raw error text. Logging starts with the updated executable and cannot reconstruct older sends. A dispatch without a result has an unknown delivery outcome.

Review and redact diagnostic output before sharing it. The agents being observed retain their own provider connections and data policies.
